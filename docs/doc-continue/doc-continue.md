# Documentation continue

Cette section est le journal de conception du projet. Elle est tenue au fil de l'eau et garde la trace des choix de conception, des problèmes rencontrés et de ce qui a été décidé pour y répondre.

Le but est de pouvoir relire le cheminement de pensée : pourquoi une solution a été retenue, ce qui a été essayé avant, ce qui n'a pas marché. La description détaillée du résultat final se trouve dans la documentation technique globale du projet, pas ici.

## Ajouter une entrée

Chaque journal est découpé par sous-système (électronique, firmware, châssis, etc.). Dans chaque partie, les entrées sont dans l'ordre chronologique : on ajoute à la suite, on ne réécrit pas les anciennes entrées, même si la solution a été abandonnée depuis.

Une entrée tient en quelques lignes et répond, quand c'est pertinent, à ces questions :

- **Constat** : ce qui a été fait ou observé.
- **Problème** : ce qui ne convenait pas.
- **Décision** : ce qui a été changé, et pourquoi.
- **Résultat** : ce que ça a donné une fois testé.

Les sujets non tranchés vont dans le tableau « Points ouverts » en fin de page, et en sortent une fois la décision prise.
